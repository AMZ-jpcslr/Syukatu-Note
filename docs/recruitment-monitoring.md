# 公式採用ページの自動取得・差分レビュー

[READMEへ戻る](../README.md) · [Supabase・Vercel設定](setup.md) · [データ構成](architecture.md)

## 概要

公開採用ページを取得し、変更された本文から募集情報を抽出して、レビュー待ちの候補を作成します。有料AI APIは必須ではありません。**ルールベースのみで動作し、OpenAI APIは使用しません。**

```text
公式URL登録 → ページ取得 → 本文ハッシュ比較
                              ├─ 変更なし → 終了
                              └─ 変更あり → ルール解析
                                              └─ 条件を満たす場合のみGemini補助
                                           ↓
                              更新候補・差分・証拠テキスト
                                           ↓
                                人が反映先と項目を選択
                                           ↓
                               承認した項目だけDBへ反映
```

自動処理は `recruitment_templates` や個人の応募を更新しません。保存先は監視URL・スナップショット・ジョブ・更新候補です。

## 導入

1. [migration 005](../supabase/migrations/202609230005_recruitment_monitor.sql) を、004まで適用済みのDBへ全文実行します。適用済みの場合は再実行しません。
2. 50社seedが未投入なら [seed.sql](../supabase/seed.sql)、次に [seed-recruitment-sources.sql](../supabase/seed-recruitment-sources.sql) を実行します。seedは再実行可能で既存情報を上書きしません。
3. VercelにSupabase接続設定とサーバー専用キーを登録します。環境変数は [README](../README.md#環境変数) を参照してください。
4. 最新コードをデプロイし、1社の手動取得とレビューを確認します。
5. 定期実行する場合は `CRON_SECRET` と `RECRUITMENT_MONITOR_ENABLED=true` を設定して再デプロイします。

ローカルデモでは外部ページを取得しません。基本機能と違い、自動取得にはサーバー専用キーが必要です。`GEMINI_API_KEY` が空でも動作します。

## 画面での使い方

### 登録済みの企業を確認する

企業詳細の「採用ページURLを追加」でURLと種別を指定します。「最新情報を取得」からジョブを開始し、**募集情報の更新**（`/templates/updates`）で取得状況を確認します。

1企業に複数URLを登録できます。種別は採用・インターン・職種詳細・イベント・MyPage・その他です。ログインが必要なページは取得できません。

### URLから応募先を追加する

企業追加ダイアログの「URLから登録」で公開URLを入力し、解析後の候補を確認します。企業・卒年度・反映先を確認してから登録します。年度が確認できなかった場合は、人の確認が必要です。

### 候補を承認する

候補には企業、募集、取得元URL、日時、解析方式、信頼度、変更前後、証拠テキストを表示します。「公式ページを開く」で原文を確認し、反映する項目にチェックします。

- 反映先は公開テンプレートか自分の応募です。公開変更には権限が必要です。
- **選んだ項目だけ**反映します。承認時に変更前の値も照合し、競合時は再確認を求めます。
- 日程のカレンダー追加は初期ON、タスク生成は初期OFFです。ユーザーが選択してから処理します。
- カレンダー全体の選考ステップ表示がOFFの場合は、その設定が優先されます。
- 公開情報を承認しても、他人の個人コピーは更新しません。
- 投稿URLは、承認しただけでは自動的にverifiedになりません。

## 公開テンプレートのレビュー権限

一般ユーザーは閲覧可能な候補を自分の応募へ取り込めます。公開テンプレートを変更できるのは投稿者またはレビュー担当者です。ユーザーが追加したURLや候補は原則そのユーザーにだけ見え、共有の監視ソースとは分離します。

seedテンプレートを確認・更新する運営担当は、Supabase SQL Editorで指定します。担当者の匿名ユーザーUUIDはSupabase Authenticationと照合してください。引き継ぎコードではありません。

```sql
insert into public.recruitment_reviewers(user_id)
values ('担当者の匿名ユーザーUUID')
on conflict do nothing;
```

レビュー担当権限は引き継ぎコードで自動移行しません。端末移行後は管理者が再指定します。監視URL・候補・監視設定・確認履歴は引き継ぎ対象で、同一URLが両側にある場合は履歴を保って統合します。

確認済み（verified）には、officialまたはcompany_mypageの情報元URLと最終確認日が必要です。情報を読まずに一括でverifiedやopenへ変更しないでください。

## ルール解析・日時の扱い

主な実装は [recruitment-rule-parser.ts](../src/services/recruitment-rule-parser.ts) です。

- 卒年度、職種、募集区分、開始・締切・開催日、ES／Webテスト／面接、選考フローを辞書・日付パターン・見出しから抽出します。
- 複数年度・職種は見出し単位で分離します。27卒の日程を28卒へ流用しません。
- `2028卒` は応募日の暦年を意味しません。`10/5` の年を2028と補完せず、開催年など明確な文脈がなければ `null` にします。
- 日付のみは `YYYY-MM-DD`、時刻が明記されていれば `YYYY-MM-DDTHH:mm:ss+09:00`。23:59は補完しません。
- 既存DATE列を維持し、`*_value` 列で日時精度を保存します。終日の開催期間は最終日を含めてカレンダーに表示します。
- 「定員に達し次第」「未定」「順次公開」「MyPageで案内」は注記・警告として保持します。日付不明は空欄のままです。
- 「エントリー受付中」でも締切がなければ、募集状況と締切の有無を別々に扱います。
- 信頼度は0〜1。Highは0.85以上、Mediumは0.65以上、Lowは0.65未満です。数値は抽出条件の充足度であり、正しさの保証ではありません。

同一本文ハッシュではルール解析・AI解析・差分候補の生成をすべてスキップします。スナップショットと候補の保存は同じトランザクションで確定します。

## Gemini fallback（任意）

プロバイダは [recruitment-ai-parser.ts](../src/services/recruitment-ai-parser.ts) に分離しています。

利用には `GEMINI_API_KEY`、`RECRUITMENT_AI_ENABLED=true` と利用設定が必要です。モデルは `RECRUITMENT_GEMINI_MODEL` で指定できます。

Geminiを呼ぶのは、変更あり・28卒の記載あり・ルール信頼度0.65未満などの条件を満たす場合だけです。変更なし、高信頼の締切を取得済み、他年度のみ、キー未設定の場合は呼びません。出力はZodのJSON Schemaと証拠引用で検証し、API失敗や不正な出力の場合はルール結果を使用します。

送信するのは**公開採用ページの本文**です。ES回答、面接メモ、志望度、ユーザーメモ、選考結果、匿名ユーザーID、引き継ぎコードは送信しません。

無料枠の有無・上限はアカウントとモデルに依存します。API料金を発生させない運用にする場合はキーを設定しないでください。プラットフォーム利用料は別です。

## キュー・Cron・コスト管理

[vercel.json](../vercel.json) は24本の「1日1回」のCronを分散配置します。各回、取得時期が来た企業をキューへ入れ、最大3社を順番に処理します。50社を同時取得せず、一括チェックは数時間かけて消化します。

| 優先度 | 取得間隔           |
| ------ | ------------------ |
| high   | 1日                |
| medium | 3.5日（週2回相当） |
| low    | 7日                |

初期50社はmediumです。企業詳細から自分の監視設定を変更できます。共有ソースのhigh指定は共有取得頻度を上げますが、個人の志望度や応募状況を公開しません。自分の監視OFFで他人の共有監視は停止しません。共有ソース自体を停止する場合は運営が `company_sources.monitor_enabled=false` にします。

- Cron API：`Authorization: Bearer CRON_SECRET` で保護
- 二重実行：DBロックとリースで防止。10分を過ぎた中断ジョブを再試行し、3回で打ち切り
- 手動取得：同一企業は10分間隔、1匿名ユーザーは1日60回まで
- AI回数：DBで月間上限を予約・管理。`RECRUITMENT_AI_MONTHLY_LIMIT` の既定は50回
- 設定画面：Geminiキーの設定有無、AI利用可否、閲覧可能なジョブの今月の解析回数（最大1000件）を表示。キー値は返さない

定期実行OFFでも手動の1社取得は可能です。一括キューを継続して処理するにはCronが必要です。VercelのCron Jobsと関数ログで実行状況を確認してください。実行時刻・本数・関数時間の制約は利用プランに依存するため、[VercelのCron制限](https://vercel.com/docs/cron-jobs/usage-and-pricing)も確認します。

## 取得制限と運用上の制約

| 項目       | 制限                                                                 |
| ---------- | -------------------------------------------------------------------- |
| クロール   | 1企業あたり最大5ページ、深さ2                                        |
| リクエスト | 約10秒でタイムアウト、HTML上限2MB                                    |
| 本文       | script・style・nav・footer等を除去し、最大50,000文字                 |
| 頻度       | 明示User-Agent、同一ホストは原則2秒以上空け、Crawl-delayも考慮       |
| robots.txt | 拒否・確認不能なら停止                                               |
| 対象       | 公開HTML。ログイン・CAPTCHA・非公開API・JS実行・PDF／画像OCRは対象外 |

別ホストへの転送・詳細ページは無条件で追いません。公式の詳細URLを確認して別ソースとして登録してください。取得失敗・timeout・robots禁止・login required・解析失敗・情報なしを区別して表示します。

SSRF対策は、プロトコル・ポート・URLの検証、全DNS応答のpublic IP確認、検証済みアドレスへのソケット固定、リダイレクト毎の再確認を行います。localhost、private／link-local、IPv6 local／mapped、metadataなどを拒否し、robots取得にも同じ制限を適用します。HTML内のスクリプトや本文中の指示は実行しません。

抽出は見出し・表の構造に依存します。複雑な職種と日程の対応は人の確認が必要です。「取得成功」は募集内容が確定していることを意味しません。公式URL・証拠テキストを確認してから反映します。
